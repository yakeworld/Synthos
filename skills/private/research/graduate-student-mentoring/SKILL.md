## 原则 (Principles)

- **锚定五大支柱**：方向一散即锚定五大支柱，定期回顾范围约束，不散于末节。
- **以代码计周**：每周自检以「新增可运行代码行数 / 图与 Table 产出」为量度，无产出之周不可谓之进。
- **卡二时即问**：卡住逾二小时必问导师，勿待穷时；疑者即明，明则速进。
- **改 AI 以自立**：AI 生码必亲加修改方算己作；不改则知其然不知其所以然，学无所成。


- [ ] 研究方向发散时已锚定五大支柱，并定期回顾范围约束，未陷入末节细节
- [ ] 每周自检完成：本周新增可运行代码行数、图/Table 产出数量均有记录，无产出之周记为无进展
- [ ] 学生是否理解代码每一行在做什么，且对 AI 生成的代码有亲自修改（未修改视为未掌握）
- [ ] 卡住超过 2 小时的问题已立即上报导师，无独自死磕耗尽时间的情况
- [ ] 代码跑不通时，导师已用 Hermes 调用 Synthos 技能库现有代码模块修复，而非重写环境
- [ ] 公开数据集数据量不足时已切换至科室内部临床数据补充样本
- [ ] 论文写作走「先中文初稿 → 导师修改 → 再翻英文」流程，统计分析配有模板（可辅以 ChatGPT）


## Genes (策略基因)

> 紧凑策略表示。条件→策略。需要深度时参考完整文档。

- **[GRAD-008]** 研究方向发散或偏离核心 → 锚定五大支柱并定期回顾范围约束，避免陷入末节细节
- **[GRAD-009]** 每周进度评估 → 以“新增可运行代码行数”及“图表/表格产出数量”作为核心量化指标，无产出视为无进展
- **[GRAD-010]** 遇到技术瓶颈卡住超过2小时 → 立即向导师求助，禁止独自死磕直至耗尽时间
- **[GRAD-011]** 使用AI生成代码 → 必须亲自修改并理解每一行逻辑，未修改则视为未掌握，不算有效学习
- **[GRAD-012]** 公开数据集数据量不足 → 切换至科室内部临床数据以补充样本
- **[GRAD-013]** 论文写作效率低下 → 采用“先写中文初稿，导师修改后再翻译英文”的流程以降低语言障碍
- **[GRAD-007]** 现有代码无法运行或环境配置失败 → 导师利用Hermes调用Synthos技能库中的现有代码模块进行修复

## 约束规则 · RULES

1. **输入约束**: 参数类型、范围、格式必须校验
2. **输出约束**: 返回值结构、编码、命名必须一致
3. **异常约束**: 错误信息必须包含上下文和恢复建议
4. **安全约束**: 不执行未验证的任意代码，不暴露内部状态

## Golden 集合 · GOLDEN SET

- **Golden Input**: 每周自检记录：本周新增 42 行可运行代码、2 张图 + 1 个 Table、已理解代码每一行、无卡超 2 小时问题、AI 生成代码已亲自修改 1 处边界条件
- **Golden Output**: 周进度达标（以代码计周：代码行数 + 图/Table 产出均有记录），方向锚定五大支柱未发散，AI 生码有可定位的学生修改记录 → 判定为有效进展
- **Golden Error**: 学生卡住数据清洗 bug 已 2.5 小时未上报 → 触发 GRAD-003（卡二时即问），导师用 Hermes 调用 Synthos 技能库现有代码模块修复，而非重写环境；AI 生码未修改则记为「未掌握」不算有效产出

> Golden 集合是测试的单一真理来源。所有改进必须通过 golden 测试。

> 违反规则的操作视为不安全，必须拒绝或隔离。

> 每项验证必须可执行、可记录、可复现。验证失败时记录原因和修复。

## 示例 · EXAMPLES

> 基于本技能 Principles / Genes / VERIFICATION 的真实流程构造的语义化示例。

1. **研究方向发散**（GRAD-001 / 锚定五大支柱 / VERIFICATION #1）
   输入：学生提出 5 个并行的新子方向，已偏离核心课题两周。
   操作：锚定五大支柱，与导师回顾范围约束，砍掉 3 个末节分支，聚焦 1 个主线并写下书面边界。
   验证：下一周自检表仅围绕该主线记录；范围约束在周报中可复查，未再发散（每周自检清单「方向发散」项）。

2. **卡住逾 2 小时**（GRAD-003 / 卡二时即问 / VERIFICATION #4）
   输入：学生调试一个数据清洗 bug 已 2.5 小时无进展。
   操作：立即上报导师，由导师用 Hermes 调用 Synthos 技能库现有代码模块修复，而非重写环境（GRAD-007）。
   验证：问题在上报后当日解决；无「独自死磕耗尽时间」记录（每周自检「卡住超 2 小时已上报」项）。

3. **AI 生码未修改**（GRAD-004 / 改 AI 以自立 / VERIFICATION #3）
   输入：学生提交了 200 行 AI 生成的代码，未做任何改动。
   操作：导师要求其逐行解释并亲自修改至少 1 处逻辑（如边界条件），改后重跑。
   验证：代码出现可定位的学生本人修改记录，且学生能复述每行作用——否则记为「未掌握」，不算有效产出（以代码计周）。
